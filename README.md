# Caspian College — веб-админка

Flask-приложение, которое полностью управляет мобильным приложением колледжа (Flutter + Firebase):
расписание и накладки, абитуриенты и приёмная, Caspian Coin и магазин мерча, новости, опросы, события,
люди. Данные — Firestore/Storage проекта `student-caspian-lol` через Firebase Admin SDK.

## Быстрый старт

```bash
pip install -r requirements.txt
tests/run_tests.sh 18000            # все тесты на эмуляторах (Java + firebase-tools)
CMS_INSECURE_COOKIES=1 python flask_app.py
```

## Академический календарь (PDF на группу)

Страница **«Расписание → Акад. календарь»** (`/academic-calendar`, `cms/routes_calendar.py`): администратор загружает
PDF академического календаря для каждой группы, студент видит его в профиле мобильного приложения (карточка
«Академический календарь»). Абитуриенты, преподаватели и клубы календарь не видят.

* **Данные.** `groups_list/{группа}.academicCalendar = {url, path, fileName, title, size, version, uploadedAt,
  uploadedBy}`; файл — Storage `academic_calendars/<slug>/<unixMillis>.pdf`, на каждую группу свой объект (`url` —
  download-URL с токеном, открывается без авторизации). Календаря нет — поля нет. Правила Firestore не менялись
  (`groups_list` читают члены колледжа); правила Storage — в репозитории приложения (`storage.rules`).
* **Загрузка.** PDF ≤ 20 МБ (сигнатура `%PDF-` в первых 1024 байтах, имя файла санитизируется), до 40 групп за раз;
  группы выбираются поиском и быстрыми кнопками («Все без календаря», «N курс»). Файл уходит в Storage один раз, на
  остальные группы копируется на стороне Storage (`bucket.copy_blob`, новый токен на каждую копию) — воркер не гонит
  20 МБ N раз. Всё или ничего: при сбое созданные объекты удаляются, документы не меняются. Замена: новый объект →
  запись (`version + 1`; чтение и запись — одной транзакцией Firestore, два админа не получат одинаковую версию и не
  оставят осиротевший файл) → удаление старого. Временные сбои Storage (5xx, обрыв связи) повторяются. Группа, которой
  нет в справочнике (она только в расписании или у студентов), получает запись в `groups_list` при загрузке.
* **Уведомление.** Переключатель «Уведомить студентов» (по умолчанию выключен, с подтверждением): пуш по топику группы
  `schedule_group_<группа>` (как у расписания, `ъ/ь` — в оба топика), `data: {type: academic_calendar, group}`. Сбой
  пуша загрузку не отменяет.
* **Связанное.** Переименование группы переносит календарь (путь в Storage от названия не зависит), удаление группы
  удаляет и PDF (раздел «Группы», пункт меню строки ведёт сюда). Действия пишутся в журнал: загрузка, замена, удаление.
* **Тесты.** `tests/run_tests.sh PORT_BASE tests.test_academic_calendar`. В эмуляторе Storage нет `copyTo` и PATCH
  метаданных (501): там код грузит те же байты повторно, а ветка `copy_blob` проверяется подменой бакета.

Разработчику модуля: начните с `tests/README.md` (API ядра, макросы, CSS/JS, тесты, скриншоты) и `/ui-kit`.
